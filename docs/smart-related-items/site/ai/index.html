Let the visitor's AI pick what to watch next

Blue Billywig demo · live walk-through
In plain English: A modern browser can run a small AI model right on the visitor's device (Chrome ships Gemini Nano for example). The page hands it a short description of the article and asks "which of our content buckets does this fit best?". The AI answers e.g. "parenting and recipes" — and the page asks the catalogue for clips with those tags. The AI never sees the whole catalogue, just helps us frame the question. The on-device path keeps the prompt entirely on the visitor's machine; the Claude / ChatGPT fallback further down the side panel does send the prompt to that vendor (same trade-off as opening any other chat tab).

Try it. Type the article's topic on the right (or pick a starter), hit Ask AI. The AI answers with one or two buckets; the page queries the SAPI for clips tagged with those buckets (plus the CC-licensed gate) and hands the results to the player.

Why doesn't the AI see the whole catalogue?

On-device models have small context windows (a few thousand tokens for Gemini Nano). Real publications have thousands of clips — that doesn't fit in a prompt and would also throw away the search engine you already have. So we give the AI the shape of the catalogue (a handful of topic buckets) and let it answer the only question it's actually good at: "what is this article about?". The Blue Billywig search engine then does the heavy lifting of finding clips that match.

How do I get Gemini Nano running in Chrome?

Quick install — Chrome ≥ 138

  1. Check the basics. ~22 GB free disk, GPU with ≥ 4 GB VRAM, unmetered connection. Windows 10+, macOS 13+, Linux or ChromeOS.
  2. Confirm your Chrome. Visit chrome://version — anything ≥ 138 will do.
  3. Enable two flags, then relaunch:
    • chrome://flags/#prompt-api-for-gemini-nano → Enabled
    • chrome://flags/#optimization-guide-on-device-model → Enabled BypassPerfRequirement (this skips the early "your machine might be too small" gate)
  4. Trigger the model download. Open DevTools console on any page and run: 
    await LanguageModel.availability()
// first time: "downloadable" or "after-download"
await LanguageModel.create()
// starts the actual download; promise resolves when the model is on disk
    Or open chrome://components, find Optimization Guide On Device Model and click Check for update. The model is a few hundred MB to a couple of GB; first download takes minutes.
  5. Verify. await LanguageModel.availability() should now return "available" (newer Chrome) or "readily" (older). Reload this page; the status banner above turns green.

If availability() keeps saying "unavailable" after the flags + restart, check chrome://gpu to confirm hardware acceleration isn't disabled. Some corporate-managed profiles disable on-device AI entirely; use the Claude / ChatGPT fallback below instead.

No on-device AI? Open it in Claude, ChatGPT or another chat tab

The prompt is plain text — any chat agent does the job. Click one of the buttons to open it pre-filled (the prompt is also copied to your clipboard as a safety net), paste the JSON answer back, hit Apply.

BB Daily editorial · live walk-through
In plain English: Scenarios ①–⑤ all keep the same anchor video and only change what plays after it. Suggests is the other way around. It changes which clip the player picks to play in the first place, using whatever SEO metadata the article already has — title, keywords, og:description, JSON-LD schema. No ?topic, no localStorage, no extra tag attribute. The end-screen panel comes along for the ride — filled from the same search results — but the headline trick here is the main clip itself.
What's different here vs the other five scenarios? In ①–⑤ the embed URL hard-codes the anchor clip ID and the smart cliplist only drives the end-screen strip. In ⑥ Suggests, the embed's clip ID is just an endpoint the player uses to bootstrap; the actual clip that plays is chosen at runtime, by the Blue Billywig search engine, from the article's metadata.

Suggests is reading the article…
Asking the Blue Billywig search engine for the best-fitting clip. The main clip the player picks isn't locked in until this answer comes back.

Try it. Pick a different article theme on the right and hit Reload. The article's metadata changes; the player re-runs its search; the main clip itself swaps to whatever Suggests ranked first. The end-screen strip, when you reach it, contains the rest of the same search results. Nothing else on the page is wired up.

Why is this different from the AI scenario?

Both pick the right video from page context, and both can drive the main clip (the AI scenario does that by classifying first and then handing the result to the host page, which can re-mount the player with the chosen anchor). Suggests is a weighted keyword search on the catalogue, built from the article's existing metadata — it runs on the Blue Billywig search engine, no model required, and it works in every browser. The AI scenario uses a model to classify the article into a topic bucket first, then queries the catalogue with that label. AI is more forgiving when the metadata is thin or generic; Suggests is faster and has zero install cost. They're complementary — a real deployment can use Suggests as the default and fall back to AI when Suggests returns a weak match.

Why does scenario ⑥ live inside the "smart related items" demo?

Fair question — Suggests' headline trick is picking the main clip, not the related-items strip. It sits in this demo for two reasons. First, the same search that picks the main clip also pre-fills the end-screen panel — so once you've watched the Suggests pick, the strip after it is also contextual, with zero extra configuration. Second, Suggests is the most "automatic" cousin of the other five techniques on this site: same publication, same catalogue, same idea ("let the page hint at the right video") — just applied one step earlier in the funnel.

The visitor's already-seen list

Suggests keeps a per-browser list of clip IDs the visitor has already watched, in localStorage.bb_player_viewed_clips. The next Suggests query skips those if a fresh clip is available. Clear it to see the same first pick again.

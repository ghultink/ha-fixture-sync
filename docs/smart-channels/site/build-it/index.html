Build it yourself — Channels with dynamic filters

Three things to set up: a smart cliplist with dynamic filters (same as the related-items demo), a Channel that includes a Cliplist block pointing at it, and a one-line embed on your page.

1 Build a smart cliplist with dynamic filters

This is identical to step 1 in the smart related items walk-through: in the Blue Billywig OVP, create a playlist of type dynamic, tick Allow dynamic filters, add at least one filter, click the plug icon, pick a data source (Query string or Local storage value).

  • Use Tags contains any of … with a sensible default fallback value.
  • Add a second filter group with a static gate so demo content stays bounded — e.g. Tags contains any of creative-commons.
  • Set a sensible limit and sort order.
  • Save. Note the cliplist's ID — you'll wire it into a Channel block in step 2.

Channel-specific caveat. The Channel widget supports Query string, Local storage and Text with macro data sources. The JavaScript source type is player-only — in a Channel it falls back to the filter's default value. If your signal is computed (e.g. read from a meta tag), have your page set a URL param or write to localStorage before the Channel mounts.

2 Create a Channel with a Cliplist block

Open Library → Channels → New in the OVP. Add at least:

  • One Cliplist block. In Content, pick the smart cliplist you saved in step 1.
  • Optionally a FeaturedHeader block on top with a few clip IDs you want to highlight by default.
  • Theme it — colours, fonts, border radius. The Channel's styling is independent of the host page.
  • Set status to Published. Note the Channel's numeric ID (visible in the URL: /library/channels/<id>).

3 Embed it on a page

One line:

<script src="https://{publication}.bbvms.com/ch/{channelId}.js" async></script>

The script appends a Channel root element where the <script> tag sits. The Channel widget reads the page's window.location.search and window.localStorage when it resolves the smart cliplist's dynamic filters, so:

  • Your CMS can drive the filter by tacking ?topic=… on the page URL.
  • A small JS snippet earlier in the page can write to localStorage to drive it from a saved preference.
  • (For the AI path:) call the on-device AI from the host page, take its answer, and set ?topic=… / localStorage before the <script> mounts.

Multiple Channels can coexist on one page. They sandbox themselves in a Shadow DOM by default so they don't inherit your site's CSS.

4 Verify

  • Open the page with ?topic=<one of your tags> and confirm the Cliplist block fills with matching videos.
  • Open the page with no ?topic — the cliplist falls back to its default value and still shows something useful.
  • Open the Channel JSON directly: https://{publication}.bbvms.com/ch/{channelId}.json. The appConfig.blocks[].config.contentId is your cliplist ID; that's the only join.

Common gotcha: the Channel's content preview in the OVP doesn't re-resolve dynamic filters either (same caveat as the player cliplist preview). To test, embed on a real page with the right URL / storage.
